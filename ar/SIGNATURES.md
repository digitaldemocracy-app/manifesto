# التوقيعات

الأشخاص الذين وقّعوا بيان Digital Democracy.

التوقيع يعني: *قرأتُ البيان وأؤيّد نقطة انطلاقه.* ولا يعني الاتفاق مع كل كلمة — فالنص مفتوح للتصحيح — ولا يرتّب أي التزام.

## كيف توقّع

التوقيع هو pull request. هكذا يبقى التوقيع سهلًا، بلا خوادم ولا استمارات، ويترك سجلًّا علنيًا دائمًا يمكن التحقق منه: سجلّ git يُظهر من أضاف كل سطر ومتى.

1. اعمل fork لهذا المستودع (أو عدّل هذا الملف مباشرة على GitHub بأيقونة القلم — فيُنشئ GitHub لك الـ fork والـ pull request).
2. أضف **سطرًا واحدًا في نهاية الجدول أدناه**. لا تعدّل أسطر الآخرين.
3. افتح الـ pull request. العنوان: `Signature: <اسمك>`.
4. يتحقق أحد المشرفين من السطر ويدمجه. هذا كل شيء.

إن كنت تفضّل ألّا تتعامل مع git، فافتح issue بقالب **Support / sign**. سيضيف أحد المشرفين سطرك نيابةً عنك، ويذكر رقم الـ issue في الـ commit، فيبقى السجلّ قابلًا للتحقق.

## ماذا تكتب

| العمود | القاعدة |
|---|---|
| Name | اسمك كما تريد أن يظهر. يُفضَّل الاسم الحقيقي لكنه ليس شرطًا. |
| GitHub | اسم مستخدمك على GitHub، اختياري. وإن ذكرتَه فيجب أن يكون الحساب الذي فتح الـ pull request أو الـ issue. |
| Where | البلد أو المنطقة أو المدينة، اختياري. بالعموم أو التحديد الذي تشاء. |
| Date | يوم توقيعك، بصيغة `YYYY-MM-DD`. |

لا تضف عناوين بريد إلكتروني ولا أرقام هواتف ولا أرقام هويات ولا أي بيانات شخصية أخرى. لا نريدها ولن ندمجها. كل ما في هذا الملف علنيّ إلى الأبد.

## التحقق

- كل سطر أُضيف عبر pull request أو issue. والـ commit الذي أضاف السطر، والحساب الذي أجراه، ظاهران في سجلّ الملف على GitHub.
- لا يدمج المشرف سطرًا إلا إذا طابق الاسمُ المكتوب فيه الـ pull request (أو الـ issue)، أو أكّد صاحب التوقيع ذلك في الـ pull request.
- لا يحذف المشرفون أي سطر إلا بطلب من صاحب التوقيع، عبر pull request آخر، يبقى هو أيضًا في السجلّ.
